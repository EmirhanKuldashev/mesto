# Анкета жизненного сценария

`/onboarding` задаёт десять последовательных вопросов: состав семьи, цель поиска, бюджет, маршруты, окружение, стиль жизни, компромиссы, будущие перемены и ценности. Черновик хранится в локальном хранилище браузера через Zustand persist и переживает обновление страницы. Кнопка «Заполнить демо» подставляет пример Максима, Анны и ребёнка семи лет; согласие она не отмечает.

Точки маршрутов выбираются на MapLibre-карте Красноярска или вводом координат. Маркер можно перемещать; сохранённую точку можно изменить или удалить. Карта использует публичные плитки OpenStreetMap, поэтому для отображения подложки нужен интернет; ввод координат остаётся доступным без неё.

Профиль сохраняется через `POST /api/profile` либо `POST /api/couple/profile`, читается через `GET /api/profile/{uuid}`. `POST /api/life-points` добавляет или изменяет точку. `POST /api/analysis/request` создаёт запись со статусом `pending` только при сохранённом согласии. Scoring engine на этом этапе отсутствует: `user_score`, `partner_score` и `family_score` остаются `null`. Предпочтения партнёра и его рабочая точка хранятся отдельно; усреднения нет.

Публичный идентификатор профиля — UUID. Существующие целочисленные первичные ключи таблиц ЭТАПА 1 сохранены внутри базы для совместимости связей. Миграция `0004_life_profile` добавляет новые поля и таблицу `analysis_requests`.

В API точка маршрута имеет поля `type`, `name`, `latitude`, `longitude`, `importance`, `frequency_per_week`. В существующей таблице `life_points` им соответствуют `kind`, `label`, геометрия `location` (SRID 4326), `importance` и `visits_per_week`. Сохранённый UUID профиля преобразуется во внутренний ключ связи `user_profile_id`.

Перед отправкой сервер проверяет положительный бюджет нужного типа, величину первоначального взноса, координаты, возраст детей, диапазоны весов и явное согласие. Черновик остаётся на устройстве пользователя, пока он не нажмёт «Сбросить» или не очистит данные браузера.
