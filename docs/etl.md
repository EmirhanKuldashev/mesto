# ETL

Поток: источник → `BaseDataAdapter.fetch()` → `validate()` → `normalize()` → `load()` → PostgreSQL/PostGIS. Реализации находятся в `backend/app/etl/`; каталоги `extract/`, `transform/`, `load/`, `validators/` оставлены для расширения по мере подключения реальных источников. Исходные файлы и адаптеры из `app/data_sources/` не входят в аналитический слой напрямую.

`python -m app.etl.seed` создаёт фиксированный набор: 7 районов, 250 POI, 12 ЖК, 60 продаж, 80 аренд, 20 будущих объектов и 8 ипотечных программ. Генерация не использует случайные числа; дата получения и версия фиксированы. Для каждой партии сохраняется SHA-256 исходных записей. Повторный запуск с той же версией пропускает вставку; изменение содержимого требует новой версии и выдаёт ошибку, если версия не изменена. Загрузка выполняется в одной транзакции, поэтому частичная партия не остаётся в БД.

Перед нормализацией Pydantic проверяет обязательное имя и диапазоны координат. Для будущих реальных адаптеров нужны дополнительные проверки: схема источника, координатная система, дубликаты внешних ID, диапазоны цен и дат, лицензия, свежесть, документ и геометрическая валидность. Неверные записи следует помещать в журнал карантина и не выдавать API. Версия источника и ограничения качества должны обновляться при каждой успешной загрузке. Расписание обновления определяется условиями конкретного источника, а не кодом аналитики.

Backend в Compose выполняет миграции и idempotent seed перед запуском FastAPI. Для локального запуска: `cd backend`, `alembic upgrade head`, `python -m app.etl.seed`, затем `uvicorn app.main:app`.
